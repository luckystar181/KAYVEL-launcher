# KAYVEL Launcher

Лаунчер Minecraft для Windows 10/11 x64 на Electron и React. **Выпуск v3S; работоспособность игровой сборки подтверждена владельцем.** Входа и аккаунтов KAYVEL нет: игрок сохраняет ник локально, whitelist ведётся на сервере. Парольный серверный мод выбирается отдельно; лаунчер не принимает его пароли.

Этот репозиторий начинается с чистой истории. Прежние API, Core, ticket bridge, клиент аккаунтов и сценарии локальных служб сюда не перенесены. Игровые файлы, Java, моды, миры, пользовательские профили и приватные ключи в репозиторий не входят. Старые установки не изменяются и автоматически не мигрируются.

## Что работает

- Локальный ник из 3–16 латинских букв, цифр и `_`.
- Выбор PNG 64×64 или 64×32 до 1 MiB, Classic/Slim, 3D-предпросмотр и отдельные копии скина без изменения исходного PNG.
- Скины выбираются только из PNG-файла; сетевого поиска по нику нет.
- Мини-игра и сохранение её рекорда.
- Проверка Ed25519, размера и SHA-256 файлов подписанного модпака; обратимые переключатели трёх конкретных модов для будущей новой установки.
- В лаунчере 0.2.2: проверка новых версий сборки при открытии и ручная кнопка «Обновить» с резервной копией. В прежнем EXE 0.2.1 этой функции нет.

**В версии лаунчера 0.2.1 выбранный PNG применяется локально при следующем запуске сборки через CustomSkinLoader.** Под блокировкой игры создаётся собственный локальный `CustomSkinAPI` в `CustomSkinLoader/KAYVEL-Local-v1`: PNG именуются по SHA-256, JSON для ника задаёт модель Classic/Slim. Предыдущие байты заменяемых собственных JSON сохраняются в `history`; чужие файлы и конфликты не перезаписываются. Источник регистрируется штатным `ExtraList`, который сам CustomSkinLoader переносит в свой конфиг при запуске. Лаунчер основной конфиг не переписывает. Скин не отправляется на сторонние сайты; видимость другим игрокам не гарантируется.

## Подготовка одной кнопкой

Кнопка «Скачать и играть»: Java 21 при необходимости → Minecraft 1.21.1 → NeoForge 21.1.252 → подписанный модпак из отдельного GitHub Release → проверка файлов → запуск. Прогресс показывает этап, полученные байты и число файлов; при неизвестном объёме индикатор неопределённый, без выдуманных процентов. После создания процесса и выхода из игры прогресс очищается. Состояние дополнительно обновляется раз в секунду и при фокусе окна; опрос не запускает Java и не повторяет запуск игры. Готовый статус — «Установлено».

**Подключён отдельный выпуск:** [`v0.2.0-v3S`](https://github.com/luckystar181/KAYVEL-mods/releases/tag/v0.2.0-v3S) — 80 JAR, 2 ресурспака и 8 файлов KubeJS из согласованного `v3S.zip`, без служебных `mods/.index`. Все выбранные игровые файлы, включая конфигурацию KubeJS, включены без изменения байтов по явному указанию владельца. Манифест подписан Ed25519; `RELEASE_MANIFEST_URL` настроен, `localProfileReleaseReady = true`. Использован прежний согласованный ключ; приватный ключ не включён в проект или выпуск. Прежние релизы не используются и не изменяются. Владелец подтвердил, что игровая сборка работает; автоматические и изолированные проверки этого выпуска не включают реальный запуск Minecraft или повторную установку игры на чистой Windows.

В переданном `kubejs/config/web_server.json` включён локальный HTTP-сервис KubeJS. Владелец после предупреждения подтвердил публикацию этого файла без изменений, включая поле `auth`; это значение теперь публичное, а не приватный секрет. Лаунчер не запускает этот сервис сам: его поведение при запуске игры определяется модом. Этот файл не настраивает вход Minecraft на игровой сервер.

Новый экземпляр создаётся только в `instances\kayvel-1.21.1-neoforge-21.1.252-v3S` внутри `userData` Electron. Старые `game`, `vanilla`, Java, моды и миры не мигрируются и не принимаются за готовую установку. Если доступная Java 21 найдена, она используется без замены; иначе закреплённая Temurin JRE устанавливается в `runtime` нового экземпляра. До создания экземпляра проверяется наличие не менее 4 ГБ свободного места; это нижний порог, не гарантия достаточного объёма для миров и дополнительных ресурсов.

Одна общая блокировка удерживается от начала подготовки до завершения всех начатых записей. Файлы создаются без перезаписи, ссылки и небезопасные пути отклоняются. Загрузки идут до шести файлов параллельно; после ошибки новые задания не начинаются, уже начатые завершаются до освобождения блокировки. `.preparation/incomplete.json` остаётся при сбое. Запись `.preparation/ready.json` содержит размеры и SHA-256 подготовленных файлов; маркер незавершённости удаляется только после финальной проверки. При повторном нажатии готовый экземпляр проверяется без скачивания. Индикатор готовности — предварительный признак, не замена полной проверке перед запуском.

Автоматического применения обновлений, автоматического восстановления и возобновления незавершённой подготовки нет. Каталог без корректной записи подготовки не принимается; изменённые файлы не исправляются автоматически. Прежние IPC установки и старые установщики Minecraft/NeoForge остаются заблокированными: новый путь не включает их запасные запросы и перезапись занятых файлов.

Запуск из лаунчера выполняется без отдельного диалога сетевой изоляции по указанию владельца. Лаунчер **не создаёт и не проверяет изоляцию**. Перед запуском NeoForge повторно проверяется под блокировкой; блокировка передаётся наблюдателю процесса и удерживается до его завершения. При неоднозначном результате без подтверждённого наблюдения за процессом повторный запуск блокируется, автоматического повтора нет. Разработка и проверка интерфейса сами по себе не запускают Minecraft, сервер или службы; не открывайте сервер в интернет без согласия владельца.

В версии лаунчера 0.2.2 старая блокировка снимается автоматически только при подтверждённом завершении владельца и зарегистрированных дочерних процессов, отсутствии маркеров незавершённой установки/подготовки/обновления и успешной проверке процессов Windows. Любой `java`/`javaw` или другой KAYVEL/Electron сохраняет блокировку; собственные renderer-потомки не мешают проверке. Неполные метаданные, неизвестные записи и неоднозначность блокируют восстановление; вне Windows автоматическое снятие отключено. Это кооперативная защита, не handle-based гарантия против враждебной подмены файловой системы.

В настройках можно выбрать максимальную ОЗУ Minecraft с шагом 512 МБ: от 2 ГБ до меньшего из 32 ГБ и объёма физической памяти минус 2 ГБ. По умолчанию — 6 ГБ в пределах доступного максимума. Выбор хранится отдельно в `game-memory.json` и передаётся Java как `-Xmx`; начальная куча — 1 ГБ (`-Xms`). Во время подготовки и игры выбор заблокирован. Папка в настройках указывает на текущий экземпляр Minecraft с модами, не на прежнюю ванильную установку. Кнопка «Открыть папку» открывает этот каталог в Проводнике; отсутствующий каталог не создаётся, вместо этого показывается подсказка скачать сборку.

При `online-mode=false` ник не подтверждает личность, а игровой трафик сам по себе не шифруется. Whitelist не заменяет проверку личности и защиту будущего парольного мода. Саморегистрации и серверного управления игроками в лаунчере нет.

## Обновление сборки без нового EXE

Функция доступна начиная с лаунчера 0.2.2. Игроку с прежней версией нужно один раз установить новый выпуск лаунчера; последующие совместимые версии **модпака** смогут загружаться без замены EXE. Сам лаунчер себя не обновляет.

При открытии выполняется проверка `https://github.com/luckystar181/KAYVEL-mods/releases/latest/download/manifest.json`. Номер версии из ответа до проверки подписи не считается доверенным: по нему выбирается только адрес подписи `releases/download/<версия>/manifest.json.sig` в том же репозитории. Ed25519 проверяется закреплённым ключом. Принимаются непустые выпуски `vX.Y.Z-v3S` для Minecraft 1.21.1 / NeoForge 21.1.252; URL файлов должны указывать на тот же репозиторий и тег. Discovery ограничен 20 секундами на запрос, без автоповтора. Ошибка сети показывается в панели и не запускает установку или игру.

Панель показывает установленную и доступную версии. Применение начинается только кнопкой «Обновить»; Minecraft после обновления автоматически не запускается. Нельзя обновляться во время подготовки, переключения модов или игры. Backend повторно проверяет подпись, установленную сборку и процессы Windows, удерживает общую блокировку; проверка процессов повторяется после загрузки перед заменой файлов. Численный откат и подмена содержимого установленного номера версии запрещены. Удаление всей локальной истории или подмена локальных записей не покрываются этой защитой.

Обновление скачивает только новые или изменённые управляемые файлы, проверяет размер и SHA-256 в staging, затем сохраняет заменяемые/удаляемые файлы и прежние подписанные метаданные в `.kayvel/updates/<UUID>/backup`. `transaction.json` связывает пути и контрольные суммы с резервными файлами `files/<номер>`. До первой замены создаётся и синхронизируется `.kayvel/update-incomplete.json`; после финальной проверки новой сборки и резервных копий маркер удаляется. Резервные копии и оставшиеся частичные загрузки автоматически не чистятся; для них нужно свободное место.

Миры, скриншоты, `servers.dat`, `options.txt`, личные конфиги вне управляемых путей, PNG-профиль и прежние установки не заменяются. Локально изменённый **управляемый** файл или конфликт нового пути с личным файлом останавливает обновление, а не перезаписывается. Это относится и к управляемым конфигам KubeJS. Состояние «отключён» сохраняется только для поддерживаемого точного имени optional-мода; новое имя JAR не наследует переключатель автоматически. Изменение только регистра пути запрещено. Ссылки, junction и жёсткие ссылки в проверяемых файлах отклоняются; защита остаётся кооперативной, а не native handle-based защитой от одновременной враждебной подмены.

Первая установка в ещё не существующий каталог выбирает проверенный latest, повторно получает манифест по неизменяемому тегу и требует точного совпадения его байтов с discovery. Уже установленный экземпляр проверяется без загрузки pinned-базовой версии и без отката; переход на новую сборку выполняется отдельной кнопкой. Папка экземпляра и личные данные не переименовываются при изменении версии модпака.

### Если обновление прервалось

Автоматического rollback или продолжения нет. Если маркер остался, запуск, установка, переключатели модов и снятие старой блокировки запрещены, даже когда процесс обновления уже завершён. Не удаляйте `update-incomplete.json`, `.kayvel/lock` или `.kayvel/updates` наугад: файлы экземпляра могут относиться к разным версиям.

Для ручного восстановления сначала закройте игру и лаунчер, сделайте отдельную копию всего экземпляра вместе с `.kayvel` и личными данными. По `transaction.json` и подписанным манифестам нужно проверить SHA-256 backup, текущих и новых файлов; вернуть заменённые/удалённые управляемые файлы и прежние метаданные как единый согласованный набор либо завершить переход на новый набор. Новый файл допустимо удалять только после подтверждения его происхождения из этой транзакции, не затрагивая пользовательские изменения. Удаление маркера и stale lock допускается лишь после полной проверки согласованности и отсутствия процессов. Готовой команды безопасного восстановления в проекте пока нет; при сомнениях сохраните копию и передайте диагностику сопровождающему.

## Транспорт подписанного модпака

Для манифеста, отдельной подписи и файлов используется HTTPS: начальный URL — GitHub Release, разрешённые перенаправления — только на GitHub Release или `release-assets.githubusercontent.com`. Перенаправления обрабатываются вручную, максимум пять; циклы, логин/пароль в URL, нестандартный порт, фрагмент и посторонний узел останавливают операцию. Автоповторов и запасных URL в этом транспорте нет, в том числе после HTTP 429/503 и обрыва соединения.

На каждый манифест, подпись или файл действует общий сетевой лимит 180 секунд, включая заголовки, перенаправления и чтение тела. Проверяются предельный размер, `Content-Length` при наличии и отсутствие сжатого HTTP-тела. По тайм-ауту поток отменяется; уже начатая локальная запись завершается до закрытия файла и снятия блокировки. Это не жёсткий лимит времени дисковых операций.

Манифест и подпись скачиваются последовательно, подпись Ed25519 проверяется до запросов файлов модпака и до локальных изменений самостоятельного установщика модпака. В общей подготовке к этому моменту Java, Minecraft и NeoForge уже могут быть записаны под маркером незавершённости; проверка подписи не предшествует всей подготовке. Размер и SHA-256 каждого файла модпака проверяются в отдельном staging до размещения без перезаписи. Частичные файлы после ошибки остаются для проверки, не возобновляются и автоматически не удаляются.

## Официальные файлы и NeoForge

Новый транспорт официальных файлов разрешает только явно перечисленные HTTPS-узлы Minecraft, Mojang, NeoForge и Maven Central, контролирует перенаправления, размер и контрольную сумму, не использует запасные адреса или автоповторы. Temurin скачивается через ограниченный GitHub-транспорт. Метаданные Minecraft, архив Java и установщик NeoForge закреплены контрольными суммами; официальные библиотеки и ресурсы проверяются по SHA-1 метаданных, затем получают локальные SHA-256 receipts. Эти receipts позволяют заметить последующие изменения, но не являются независимой подписью всех игровых файлов.

Штатный установщик NeoForge с `--install-client` не вызывается. Из закреплённого installer JAR читаются профиль и client patch; отдельно загружаются библиотеки. Вместо сетевого `DOWNLOAD_MOJMAPS` планируется контролируемая загрузка mappings. Затем предусмотрены пять локальных Java-процессоров: `MCP_DATA`, `MERGE_MAPPING`, `jarsplitter`, `AutoRenamingTool`, `binarypatcher`. Серверные процессоры исключены. Для каждого предусмотрен отдельный журнал в `.preparation`, проверка незанятых выходных путей и ненулевых результатов; эти процессоры ещё не выполнялись при проверке разработки.

По исходникам точной FML `4.0.44` подтверждено: `LibraryFinder` использует `-DlibraryDirectory`, `ProductionClientProvider` находит Minecraft `srg` и `extra`, а `NeoForgeClientLaunchHandler` — patched `client` и `universal`. Поэтому отсутствие этих четырёх JAR в обычном classpath не означает ошибку; они должны находиться в Maven-структуре `libraries`. Все четыре обязательны в проверке receipts. Подстановка `${library_directory}` и `${classpath_separator}` отдельно проверяется реальным генератором аргументов `@xmcl/core`, без запуска Java. План соответствует Minecraft `1.21.1`, NeoForm `20240808.144430`, NeoForge `21.1.252`; это статическая проверка, не подтверждение успешной игровой установки.

## Разработка

Нужны Windows 10/11 x64, Node.js 24 и npm 11. Установка зависимостей требует сети и может выполнить установочные скрипты зависимостей, включая загрузку Electron; запускайте её осознанно:

```powershell
npm ci --fetch-retries=0 --no-audit --no-fund
```

Проверка типов, сборка и изолированные тесты:

```powershell
npm run check
npm test
```

`npm test` собирает приложение и запускает Node-тесты из `tests/`. В этом репозитории нет прежних тестов auth/Core, интеграционных служб и тестов, поднимающих HTTP-серверы. Ответы сети в тестах подменяются; Minecraft, серверы и Java-установщики не запускаются. Некоторые тесты создают дочерние процессы Node и временные файлы; Windows-тесты также компилируют установщик штатным C#-компилятором, упаковывают маленький тестовый ZIP и проверяют native-ядро без сети и запуска лаунчера. По умолчанию используется системный временный каталог; его можно задать через `TEMP`, `TMP` и `KAYVEL_TEST_TMPDIR`.

Для v3S прошли 226 автоматических тестов и проверка типов. Дополнительно в отдельной копии portable с отдельным профилем проверены настоящий UI/IPC, сохранение PNG, отсутствие поиска по нику, неизменность ОЗУ и переходы статуса через подменённый IPC: запуск → игра работает → выход, включая пропущенное уведомление выхода. Сеть и дочерние игровые процессы были запрещены. Настоящий payload установщика проверен native-ядром из итогового EXE: все 2735 распакованных файлов совпали с portable по SHA-256, ярлык в тестовой папке указывает на нужный EXE. Эти проверки не являются запуском Minecraft или установкой на чистой Windows.

Для обновления лаунчера 0.2.1 прошли 288 автоматических тестов и проверка типов, включая локальную передачу PNG в CustomSkinLoader и восстановление блокировки с проверкой реальных процессов Windows. Native-ядром нового EXE проверены все 2738 файлов payload: SHA-256 совпадают с portable; создание независимого ярлыка проверено в отдельной папке. Отображение скина непосредственно в Minecraft требует пользовательской проверки.

Для лаунчера 0.2.2 с updater прошли **358 тестов**: discovery и подпись, численные версии, приватный IPC candidate, блокировка конкурирующих операций, сохранность личных файлов, disabled-моды, локальные конфликты, нехватка места и изменения metadata/staging/backup. Рабочий пользовательский экземпляр для этих тестов не использовался.

Окно читает локальные данные Electron из `%APPDATA%\kayvel-launcher`; это не обязательно пустой профиль. Для изолированной проверки используйте отдельный тестовый профиль, а не удаляйте прежнюю Java, моды или миры. Перед добавлением новых тестов отдельно проверьте их сетевое поведение.

## Переносимая папка Windows

```powershell
npm run package:portable -- --output-name KAYVEL-local-preview
```

Результат — `dist\portable\KAYVEL-local-preview\KAYVEL.exe` и файлы рядом. Переносить нужно **всю папку**, не один EXE. Упаковщик использует уже установленный Electron и локальный npm-кэш для production-зависимостей (`npm ci --offline --omit=dev --ignore-scripts`). Сам он не запрашивает сеть и не запускает install-скрипты. Недостающий кэш приводит к остановке без сетевого fallback.

Существующий результат не перезаписывается. При ошибке частичная папка остаётся для проверки; исправьте причину и выберите новое имя, а не повторяйте операцию наугад. Упаковщик переносит только зависимости `main.js` и `preload.cjs` и отклоняет ссылки на прежние модули аккаунтов.

EXE не подписан Authenticode и не является установщиком. Не отключайте защиту Windows ради его запуска. Проверка на текущем компьютере не заменяет проверку на чистой Windows. В папку приложения не входят Minecraft, управляемая Java и моды. Локальные данные по умолчанию хранятся отдельно от EXE в каталоге Electron, а не внутри переносимой папки.

## Один EXE для установки

Пользователь скачивает только [`KAYVEL-Setup-v3S.exe`](https://github.com/luckystar181/KAYVEL-launcher/releases/download/v0.2.2-v3S/KAYVEL-Setup-v3S.exe). Это небольшой WinForms-загрузчик на штатном .NET Framework Windows 10/11. После нажатия «Установить» он скачивает `KAYVEL-v3S-windows-x64.zip` из того же выпуска, проверяет закреплённые размер и SHA-256, распаковывает в новый каталог `%LOCALAPPDATA%\Programs\KAYVEL\v3S-<UUID>` и создаёт ярлык `KAYVEL v3S` на рабочем столе. Если такое имя уже занято, выбирается новое; прежний ярлык не заменяется. Права администратора не требуются. Открытие лаунчера после установки — отдельная кнопка; Minecraft автоматически установщиком не запускается.

HTTPS разрешён только для закреплённого GitHub-репозитория и `release-assets.githubusercontent.com`. Перенаправления ручные, максимум пять; общий лимит загрузки — 15 минут, без автоповторов. Отмена прерывает загрузку или распаковку. ZIP проверяется повторно до распаковки, небезопасные пути, ссылки и дубликаты отклоняются. Нужны минимум 2 ГБ для установки лаунчера; место для игры проверяется отдельно. При ошибке частичные файлы остаются в `.setup-<UUID>` для проверки. Автообновления и удаления старых установок нет: повторная установка создаёт отдельную папку, а данные Electron остаются отдельно.

Сборка после создания portable:

```powershell
node scripts/package-setup.mjs dist/portable/KAYVEL-v3S dist/setup/KAYVEL-v3S
```

Папка результата должна быть новой. Публикуются EXE, ZIP и `SHA256SUMS.txt` в выпуске лаунчера `v0.2.2-v3S`; для пользователя достаточно EXE. Установщик и лаунчер **не подписаны Authenticode**: Windows может показать предупреждение SmartScreen. Не отключайте защиту ради запуска. SHA-256 payload и Ed25519 модпака не заменяют Authenticode и проверку на чистой Windows.

## Профиль и сохранность данных

Ник и скин сохраняются локально в `local-player` внутри `userData` Electron. Новый PNG или смена ника создают отдельную копию `skin-copies\<UUID>\<ник>.png`; прежние копии автоматически не удаляются. При смене offline-ника может измениться игровая личность и доступ к вещам в мире.

История ограничена 256 ревизиями. Повреждённая или неполная запись блокирует дальнейшие изменения; отсутствующий PNG не восстанавливается автоматически. После аварии могут остаться частичные файлы или `profile.lock`. Не удаляйте их наугад.

SHA-256 связывает ревизии, но не превращает их в защищённый журнал или резервную копию: удаление последней ревизии или полная локальная подмена могут остаться незамеченными. Блокировки кооперативные; внешние программы способны менять файлы. Резервирование и восстановление требуют отдельного решения.

Изменённые, отсутствующие или неоднозначные файлы приводят к остановке, не к автоматическому ремонту. Сбой между созданием жёсткой ссылки и удалением исходного имени может оставить два имени одних данных; не удаляйте их без проверки.

Владелец сборки подтвердил её проверку и права на публичное распространение всех переданных JAR, включая `ragdoll_corpse` и `sable_player_ragdoll`; независимая юридическая проверка не проводилась. Если удалить и метку, и манифест, прежний модпак не всегда отличим от отдельной неуправляемой установки NeoForge; новый путь дополнительно требует запись подготовки.

## Отдельный подписанный выпуск

`scripts/prepare-github-release.mjs` локально готовит новый набор из отдельно выбранных `mods\*.jar`, `resourcepacks\*.zip`, `kubejs\client_scripts\*.js`, `kubejs\startup_scripts\*.js`, `kubejs\config\*.json` и PNG в `kubejs\assets\kubejs\textures\block` и `item`. Остальные пути не разрешены. Установщик проверяет каждый родительский каталог вложенных файлов, не принимает ссылки и не перезаписывает существующие файлы. Инструмент требует нового тега, новой папки результата, подтверждения прав и приватного Ed25519-ключа **вне проекта и исходной папки**. Сам инструмент ничего не публикует. Подтверждение оператора не является независимой проверкой лицензий; для известных ограниченных файлов есть дополнительное подтверждение.

Приватные ключи подписи, токены GitHub и серверные пароли нельзя помещать в git, приложение или GitHub Release. Публикуемые конфигурации следует считать общедоступными; поле `auth` в явно согласованном конфиге не должно использоваться как приватный секрет в других средах. После подписи нельзя менять байты манифеста и файлов. Прежний публичный ключ сохранён; URL настроен на v3S. При подготовке и проверке публикации сверяются Ed25519, SHA-256, размеры и точные байты всех 90 выбранных игровых файлов. Исходный ZIP, старые опубликованные файлы и ключи не меняются автоматически.

Подпись подтверждает целостность относительно закреплённого ключа, но не защищает от всех локальных изменений. В лаунчере 0.2.2 численный откат и изменение установленного номера запрещены; прежний EXE 0.2.1 не применяет новые версии к установленному экземпляру.

### Публикация следующего модпака

1. Подготовить новый уникальный численный тег `vX.Y.Z-v3S`, больший текущего, и новую папку результата. Сохранять совместимые версии Minecraft/NeoForge и формат манифеста. Прежние теги, assets, исходный ZIP и существующие build-папки не изменять.
2. Подготовить файлы штатным `scripts/prepare-github-release.mjs`, подписать `manifest.json` прежним Ed25519-ключом вне репозитория. Все URL в манифесте должны вести в `luckystar181/KAYVEL-mods/releases/download/<новый тег>/…`. Изменение ключа или формата потребует отдельного выпуска лаунчера.
3. В новом draft-релизе **репозитория модпака**, не лаунчера, разместить весь набор файлов, `manifest.json` и `manifest.json.sig`. До перевода в latest проверить размеры, SHA-256, подпись и наличие каждого asset. Не публиковать частичный комплект как latest.
4. Опубликовать полный стабильный выпуск и назначить его latest в GitHub. Pre-release/draft не считать каналом обновлений. Проверить фактически скачанные по latest и immutable URL байты: они должны совпадать с локальным подписанным манифестом; сверить подпись и все payload. GitHub latest — изменяемый указатель, а не криптографическая гарантия самого нового номера.
5. Проверить обнаружение, чистую установку и явное обновление старого экземпляра на отдельном тестовом профиле, включая сохранность личных файлов. Установленный модпак с локально изменёнными управляемыми конфигами намеренно даст конфликт; не обходить проверку удалением его метаданных.

Для обновления только модпака не нужно пересобирать установщик или менять его ZIP. Функция updater распространяется отдельным выпуском лаунчера 0.2.2; assets опубликованной 0.2.1 не заменяются.

До публичного размещения игровых служб отдельно согласуются архитектура, защита каналов, секреты, хранилище, резервирование, восстановление и расходы. В этом репозитории нет развёртывания игрового сервера и платной инфраструктуры.
