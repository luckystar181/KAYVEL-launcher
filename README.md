# KAYVEL Launcher

Лаунчер Minecraft для Windows 10/11 x64 на Electron и React. **Выпуск v3S; работоспособность базовой игровой сборки подтверждена владельцем. Добавление Coasters 0.1.6 в v0.2.4 не проверено запуском игры или сервера.** Входа и аккаунтов KAYVEL нет: игрок сохраняет ник локально, whitelist ведётся на сервере. Парольный серверный мод выбирается отдельно; лаунчер не принимает его пароли.

Этот репозиторий начинается с чистой истории. Прежние API, Core, ticket bridge, клиент аккаунтов и сценарии локальных служб сюда не перенесены. Игровые файлы, Java, моды, миры, пользовательские профили и приватные ключи в репозиторий не входят. Старые установки не изменяются и автоматически не мигрируются.

## Что работает

- Локальный ник из 3–16 латинских букв, цифр и `_`.
- Начиная с 0.2.10: без локальных PNG, выбора/предпросмотра скина и клиентского применения. Скинами управляет серверный Skin Restorer, установленный владельцем; лаунчер его не устанавливает и не настраивает.
- Кнопка «Гайд по скину» / “Skin guide” в верхнем меню открывает отдельное модальное окно: подготовка PNG, загрузка на Postimages, прямая ссылка `i.postimg.cc` и команды сервера для Classic/Steve и Slim/Alex. Гайд доступен на русском и английском, не загружает PNG и не меняет профиль или игровые файлы.
- Ник и история профиля сохраняются. Старые поля скина игнорируются; новые ревизии содержат только ник (версия профиля 3). Старые PNG, конфиги и ревизии автоматически не удаляются.
- Мини-игра и сохранение её рекорда.
- Проверка Ed25519, размера и SHA-256 файлов подписанного модпака; обратимые переключатели трёх конкретных модов для будущей новой установки.
- Начиная с лаунчера 0.2.2: проверка новых версий сборки при открытии и ручная кнопка «Обновить» с резервной копией. В прежнем EXE 0.2.1 этой функции нет.
- В диагностической версии 0.2.3: отдельный этап проверки доступной сборки, hostname и безопасный код сетевой причины вместо одного `fetch failed`. Это диагностика, а не обход сетевых ограничений.
- С версии 0.2.4: отдельная кнопка «Отменить загрузку», ожидание завершения записей и собственных processors, подтверждаемый повтор только неполной подготовки с резервной копией. После повтора игра автоматически не запускается; маркеры установки/обновления и неоднозначное состояние остаются блокирующими.
- В тестовой версии 0.2.5: один EXE со встроенными лаунчером и официальным архивом Java, без сетевой загрузки payload/Java; Minecraft, NeoForge и модпак требуют сети.
- В версии 0.2.6 было добавлено предупреждение «Не устанавливайте FFmpeg»; в 0.2.7 оно удалено, потому что FFmpeg теперь готовит лаунчер. Подпись поля ника и тёмная прокрутка сохранены.
- В версии 0.2.7: минималистичное меню с заметным 3D-скином, автоматическая подготовка FFmpeg/FFprobe для Vista и проверка обновлений самого лаунчера; загрузка и открытие отдельного установщика — только после явного подтверждения. Подписанные Ed25519-метаданные канала распространяются вместе с выпуском `v0.2.7-v3S`.

### Гайд по серверному скину (локальное дополнение 0.2.10)

Верхняя кнопка «Гайд по скину» открывает native HTML `<dialog>` в оформлении мини-игры. Окно прокручивается, закрывается крестиком, Escape и нажатием на затемнение за его пределами; после закрытия фокус возвращается к кнопке. Есть русский и английский текст.

1. Подготовить PNG текстуры Minecraft, обычно 64×64, и выбрать модель Classic/Steve или Slim/Alex.
2. Открыть `https://postimages.org/`, загрузить PNG без изменения размера и без срока удаления. Изображение станет публичным по ссылке.
3. Скопировать именно **Direct link** к PNG на `https://i.postimg.cc/.../skin.png`, не страницу просмотра `postimg.cc` и не один адрес хостинга.
4. На сервере выполнить одну из команд, заменив пример своей полной ссылкой и сохранив кавычки:

```text
/skin set web classic "https://i.postimg.cc/XXXX/skin.png"
/skin set web slim "https://i.postimg.cc/XXXX/skin.png"
```

`XXXX/skin.png` — только пример. Skin Restorer устанавливает администратор на сервере; лаунчер не устанавливает мод, не отправляет команды и не принимает локальные PNG. Синтаксис сверён с [документацией Skin Restorer](https://github.com/Suiranoil/SkinRestorer/wiki/Commands); ссылка [Modrinth 1.21.1](https://modrinth.com/mod/skinrestorer?g=1.21.1) доступна из гайда. Внешний браузер открывается только по нажатию: IPC принимает лишь три фиксированных идентификатора (`postimages`, `modrinth`, `commands`), проверяет отправителя и отвергает произвольные URL/унаследованные свойства. При ошибке браузера в окне появляются адреса для ручного открытия.

Дополнение собрано отдельно в `dist/portable/KAYVEL-v3S-0.2.10-skin-guide`; соответствующий установщик — `dist/setup/KAYVEL-v3S-0.2.10-skin-guide/KAYVEL-Setup-v3S.exe`. Прежние IPC установки и старые установщики Minecraft/NeoForge остаются заблокированными: новый путь не включает их запасные запросы и перезапись занятых файлов.

Запуск из лаунчера выполняется без отдельного диалога сетевой изоляции по указанию владельца. Лаунчер **не создаёт и не проверяет изоляцию**. Перед запуском NeoForge повторно проверяется под блокировкой; блокировка передаётся наблюдателю процесса и удерживается до его завершения. При неоднозначном результате без подтверждённого наблюдения за процессом повторный запуск блокируется, автоматического повтора нет. Разработка и проверка интерфейса сами по себе не запускают Minecraft, сервер или службы; не открывайте сервер в интернет без согласия владельца.

В версии лаунчера 0.2.2 старая блокировка снимается автоматически только при подтверждённом завершении владельца и зарегистрированных дочерних процессов, отсутствии маркеров незавершённой установки/подготовки/обновления и успешной проверке процессов Windows. Любой `java`/`javaw` или другой KAYVEL/Electron сохраняет блокировку; собственные renderer-потомки не мешают проверке. Неполные метаданные, неизвестные записи и неоднозначность блокируют восстановление; вне Windows автоматическое снятие отключено. Это кооперативная защита, не handle-based гарантия против враждебной подмены файловой системы.

В настройках можно выбрать максимальную ОЗУ Minecraft с шагом 512 МБ: от 2 ГБ до меньшего из 32 ГБ и объёма физической памяти минус 2 ГБ. По умолчанию — 6 ГБ в пределах доступного максимума. Выбор хранится отдельно в `game-memory.json` и передаётся Java как `-Xmx`; начальная куча — 1 ГБ (`-Xms`). Во время подготовки и игры выбор заблокирован. Папка в настройках указывает на текущий экземпляр Minecraft с модами, не на прежнюю ванильную установку. Кнопка «Открыть папку» открывает этот каталог в Проводнике; отсутствующий каталог не создаётся, вместо этого показывается подсказка скачать сборку.

При `online-mode=false` ник не подтверждает личность, а игровой трафик сам по себе не шифруется. Whitelist не заменяет проверку личности и защиту будущего парольного мода. Саморегистрации и серверного управления игроками в лаунчере нет.

## Обновление сборки без нового EXE

Функция доступна начиная с лаунчера 0.2.2. Игроку с прежней версией нужно один раз установить новый выпуск лаунчера; последующие совместимые версии **модпака** смогут загружаться без замены EXE. Начиная с 0.2.7 отдельно проверяются обновления самого лаунчера; порядок подтверждения описан ниже.

При открытии выполняется проверка `https://github.com/luckystar181/KAYVEL-mods/releases/latest/download/manifest.json`. Номер версии из ответа до проверки подписи не считается доверенным: по нему выбирается только адрес подписи `releases/download/<версия>/manifest.json.sig` в том же репозитории. Ed25519 проверяется закреплённым ключом. Принимаются непустые выпуски `vX.Y.Z-v3S` для Minecraft 1.21.1 / NeoForge 21.1.252; URL файлов должны указывать на тот же репозиторий и тег. Discovery ограничен 20 секундами на запрос, без автоповтора. Ошибка сети показывается в панели и не запускает установку или игру.

Панель показывает установленную и доступную версии. Применение начинается только кнопкой «Обновить»; Minecraft после обновления автоматически не запускается. Нельзя обновляться во время подготовки, переключения модов или игры. Backend повторно проверяет подпись, установленную сборку и процессы Windows, удерживает общую блокировку; проверка процессов повторяется после загрузки перед заменой файлов. Численный откат и подмена содержимого установленного номера версии запрещены. Удаление всей локальной истории или подмена локальных записей не покрываются этой защитой.

Обновление скачивает только новые или изменённые управляемые файлы, проверяет размер и SHA-256 в staging, затем сохраняет заменяемые/удаляемые файлы и прежние подписанные метаданные в `.kayvel/updates/<UUID>/backup`. `transaction.json` связывает пути и контрольные суммы с резервными файлами `files/<номер>`. До первой замены создаётся и синхронизируется `.kayvel/update-incomplete.json`; после финальной проверки новой сборки и резервных копий маркер удаляется. Резервные копии и оставшиеся частичные загрузки автоматически не чистятся; для них нужно свободное место.

Сам updater модпака не заменяет миры, скриншоты, `servers.dat`, `options.txt`, личные конфиги вне управляемых путей, PNG-профиль и прежние установки. Отдельная логика лаунчера 0.2.8 перед запуском один раз дополнит клавиши и список серверов с резервными копиями, как описано выше. Локально изменённый **управляемый** файл или конфликт нового пути с личным файлом останавливает обновление, а не перезаписывается. Это относится и к управляемым конфигам KubeJS. Состояние «отключён» сохраняется только для поддерживаемого точного имени optional-мода; новое имя JAR не наследует переключатель автоматически. Изменение только регистра пути запрещено. Ссылки, junction и жёсткие ссылки в проверяемых файлах отклоняются; защита остаётся кооперативной, а не native handle-based защитой от одновременной враждебной подмены.

Первая установка в ещё не существующий каталог выбирает проверенный latest, повторно получает манифест по неизменяемому тегу и требует точного совпадения его байтов с discovery. Уже установленный экземпляр проверяется без загрузки pinned-базовой версии и без отката; переход на новую сборку выполняется отдельной кнопкой. Папка экземпляра и личные данные не переименовываются при изменении версии модпака.

### Если обновление прервалось

Автоматического rollback или продолжения нет. Если маркер остался, запуск, установка, переключатели модов и снятие старой блокировки запрещены, даже когда процесс обновления уже завершён. Не удаляйте `update-incomplete.json`, `.kayvel/lock` или `.kayvel/updates` наугад: файлы экземпляра могут относиться к разным версиям.

Для ручного восстановления сначала закройте игру и лаунчер, сделайте отдельную копию всего экземпляра вместе с `.kayvel` и личными данными. По `transaction.json` и подписанным манифестам нужно проверить SHA-256 backup, текущих и новых файлов; вернуть заменённые/удалённые управляемые файлы и прежние метаданные как единый согласованный набор либо завершить переход на новый набор. Новый файл допустимо удалять только после подтверждения его происхождения из этой транзакции, не затрагивая пользовательские изменения. Удаление маркера и stale lock допускается лишь после полной проверки согласованности и отсутствия процессов. Готовой команды безопасного восстановления в проекте пока нет; при сомнениях сохраните копию и передайте диагностику сопровождающему.

Подготовка выполняется под общей игровой блокировкой после проверки базового экземпляра и перед запуском, в том числе для уже установленной сборки. Сначала создаётся отдельная попытка `.kayvel/ffmpeg-attempts/9.0.2-*`; готовый проверенный каталог переносится целиком. Существующий корректный комплект используется без сети, несовпадающий или неполный — блокирует запуск без перезаписи. Частичные попытки сохраняются, автоповтора и автоматической очистки нет. FFmpeg не входит в core receipts: его сбой не требует заново скачивать Minecraft, Java или NeoForge и не снимает посторонние маркеры незавершённости.

## Обновление самого лаунчера

В версии 0.2.7 при открытии проверяется отдельный `https://github.com/luckystar181/KAYVEL-launcher/releases/latest/download/launcher-update.json`. В варианте `minimal-ui` отсутствие метаданных (HTTP 404 с `github.com` при обнаружении манифеста) показывает нейтральное «Канал обновлений пока недоступен»: актуальность версии не подтверждена, но подготовка игры доступна. Это не успешная проверка и не разрешение установить непроверенный EXE. Ошибки подписи, TLS, HTTP 403/429/500 и 404 CDN остаются ошибками. Старый опубликованный EXE 0.2.6 не умеет проверять обновления лаунчера: для перехода на 0.2.7 нужна обычная ручная установка.

До доверия номеру версия используется только для выбора подписи по неизменяемому тегу `vX.Y.Z-v3S/launcher-update.json.sig`. Ed25519 проверяется прежним закреплённым ключом. Манифест связывает стабильную численную версию, платформу `win32-x64`, размер, SHA-256 и точный URL `KAYVEL-Setup-v3S.exe` в том же выпуске `luckystar181/KAYVEL-launcher`. Применяются HTTPS, ограничения перенаправлений GitHub/CDN и сетевые лимиты; ошибку нельзя обойти отключением подписи или TLS. Discovery ничего не устанавливает, численный откат и повторная установка текущей версии запрещены.

Для загрузки нужна кнопка панели, затем native-подтверждение с **отменой по умолчанию**. Проверенная подпись и версия повторно сверяются в backend, аргументы renderer не задают URL или установщик. Загрузка идёт в отдельную новую папку `<userData>/launcher-updates/<версия>-*`; предыдущие попытки не заменяются и автоматически не удаляются. Размер и SHA-256 EXE проверяются перед открытием. Отмена останавливает сеть и ждёт завершения начатых записей; конкурирующие подготовка, запуск и изменение модов блокируются. При ошибке EXE не открывается.

В опубликованной версии 0.2.8 после подтверждения лаунчер только открывает отдельный установщик: тот требует собственной кнопки установки и создаёт новую папку/независимый ярлык. Текущее окно само не закрывается; перед запуском новой версии закройте старое вручную.

В версии 0.2.9 установщик получил тёмное оформление, отдельные этапы и прогресс. Он обновляет существующий собственный ярлык KAYVEL вместо создания очередного дубликата. Исходные байты заменяемых ярлыков сохраняются в `<LocalAppData>/Programs/KAYVEL/.shortcut-backups/<UUID>`; собственные дубликаты переносятся туда же. Чужие, изменённые, переименованные и повреждённые ярлыки сохраняются. Прежние установки и игровые данные не удаляются.

При обновлении из лаунчера с поддержкой нового протокола старое окно остаётся работать до успешной установки и повторной проверки отсутствия игры/других операций. Затем установщик получает подтверждение по приватному каналу, лаунчер штатно закрывает только себя, а установщик ждёт завершения именно этого процесса и открывает новую версию. Отмена установки, ошибка или неподтверждённый переход не дают команду закрытия старого окна; Minecraft автоматически не запускается. При сбое перехода установщик предлагает закрыть старый лаунчер и открыть новый вручную. **Первый переход с опубликованной 0.2.8 и более старых клиентов остаётся ручным:** они не поддерживают этот протокол. Полный установщик 0.2.9 и подписанные метаданные опубликованы как стабильный Latest; автоматический переход станет доступен из 0.2.9 при следующем совместимом обновлении.

Это не бесшумная замена работающего EXE. Проверка подписи метаданных не является Authenticode-подписью установщика и не гарантирует криптографически самый свежий выпуск.

### Подготовка канала обновлений лаунчера

1. Собрать и проверить отдельные portable и setup для нового стабильного `X.Y.Z`, не меняя прежние каталоги и assets.
2. Вызвать `node scripts/prepare-launcher-update.mjs --installer "<новый EXE>" --version X.Y.Z --private-key "<внешний Ed25519 PEM>" --output "<новая внешняя папка>"`. Родитель output должен существовать; ключ и результат должны находиться вне репозитория, ключ не должен попадать в output. Инструмент сверяет ключ с закреплённым публичным ключом и отказывается переиспользовать output. Для выпуска `v0.2.7-v3S` метаданные подготовлены прежним внешним Ed25519-ключом; ключ не входит в репозиторий, portable или assets.
3. В новом draft-релизе **лаунчера** с тегом `vX.Y.Z-v3S` разместить проверенный EXE, диагностический ZIP, контрольные суммы, `launcher-update.json` и `launcher-update.json.sig`. Прежние выпуски не изменять; ключ не публиковать. Подписанные байты после подписи не редактировать.
4. Только после сверки подписи, SHA-256 и состава полного выпуска публиковать его и назначать latest. Отдельно проверить discovery по latest и подпись по immutable URL из изолированного профиля. Эти действия не выполняются сборочными скриптами автоматически.

## Транспорт подписанного модпака

Для манифеста, отдельной подписи и файлов используется HTTPS: начальный URL — GitHub Release, разрешённые перенаправления — только на GitHub Release или `release-assets.githubusercontent.com`. Перенаправления обрабатываются вручную, максимум пять; циклы, логин/пароль в URL, нестандартный порт, фрагмент и посторонний узел останавливают операцию. Автоповторов и запасных URL в этом транспорте нет, в том числе после HTTP 429/503 и обрыва соединения.

На каждый манифест, подпись или файл действует общий сетевой лимит 60 минут и отдельный лимит простоя 180 секунд. Непустые порции данных сбрасывают лимит простоя; медленная, но продолжающаяся передача больше не обрывается через три минуты. Ограничения охватывают заголовки, перенаправления и чтение тела. Проверяются предельный размер, `Content-Length` при наличии и отсутствие сжатого HTTP-тела. По тайм-ауту поток отменяется; уже начатая локальная запись завершается до закрытия файла и снятия блокировки. Это не жёсткий лимит времени дисковых операций.

Манифест и подпись скачиваются последовательно, подпись Ed25519 проверяется до запросов файлов модпака и до локальных изменений самостоятельного установщика модпака. В общей подготовке к этому моменту Java, Minecraft и NeoForge уже могут быть записаны под маркером незавершённости; проверка подписи не предшествует всей подготовке. Размер и SHA-256 каждого файла модпака проверяются в отдельном staging до размещения без перезаписи. Частичные файлы после ошибки остаются для проверки, не возобновляются и автоматически не удаляются.

С версии 0.2.3 ошибки запроса и чтения ответа показывают hostname фактически отказавшего узла (включая GitHub CDN) и известный код DNS, соединения или TLS. Вложенные и агрегированные причины распознаются без вывода исходных сообщений, полных URL, query-параметров и приватных подробностей. Тайм-аут и HTTP-статус также содержат hostname; ошибки локальной записи не выдаются за сетевые. При первой загрузке discovery выделен в отдельный этап до подготовки экземпляра. Повтор возможен только по явному действию; проверки подписи, доверенных узлов и блокировок не отключаются. Если браузер скачивает манифест, а лаунчер нет, передайте полное новое сообщение: браузер и Node/Electron могут использовать разные сетевые настройки и хранилища доверия.

## Официальные файлы и NeoForge

Новый транспорт официальных файлов разрешает только явно перечисленные HTTPS-узлы Minecraft, Mojang, NeoForge и Maven Central, контролирует перенаправления, размер и контрольную сумму, не использует запасные адреса или автоповторы. В выпуске 0.2.5 закреплённый архив Temurin входит в лаунчер и не скачивается при подготовке; при отсутствии или повреждении встроенного ZIP подготовка останавливается без сетевого fallback. Метаданные Minecraft, архив Java и установщик NeoForge закреплены контрольными суммами; официальные библиотеки и ресурсы проверяются по SHA-1 метаданных, затем получают локальные SHA-256 receipts. Эти receipts позволяют заметить последующие изменения, но не являются независимой подписью всех игровых файлов.

Штатный установщик NeoForge с `--install-client` не вызывается. Из закреплённого installer JAR читаются профиль и client patch; отдельно загружаются библиотеки. Вместо сетевого `DOWNLOAD_MOJMAPS` планируется контролируемая загрузка mappings. Затем предусмотрены пять локальных Java-процессоров: `MCP_DATA`, `MERGE_MAPPING`, `jarsplitter`, `AutoRenamingTool`, `binarypatcher`. Серверные процессоры исключены. Для каждого предусмотрен отдельный журнал в `.preparation`, проверка незанятых выходных путей и ненулевых результатов; эти процессоры ещё не выполнялись при проверке разработки.

По исходникам точной FML `4.0.44` подтверждено: `LibraryFinder` использует `-DlibraryDirectory`, `ProductionClientProvider` находит Minecraft `srg` и `extra`, а `NeoForgeClientLaunchHandler` — patched `client` и `universal`. Поэтому отсутствие этих четырёх JAR в обычном classpath не означает ошибку; они должны находиться в Maven-структуре `libraries`. Все четыре обязательны в проверке receipts. Подстановка `${library_directory}` и `${classpath_separator}` отдельно проверяется реальным генератором аргументов `@xmcl/core`, без запуска Java. План соответствует Minecraft `1.21.1`, NeoForm `20240808.144430`, NeoForge `21.1.252`; это статическая проверка, не подтверждение успешной игровой установки.

## Диагностическая версия 0.2.7-diagnostic.1

Отдельная локальная сборка для повторяющегося сбоя проверки процессов на Windows 10. Вместо длинного `Command failed: ...` выводятся ограниченные диагностические поля: численный/системный код, принудительное завершение и лимит 15 с, сигнал, распознанные HRESULT, категория и FullyQualifiedErrorId PowerShell. Сырые команда, stdout и stderr не показываются; исходная ошибка сохраняется в `cause`. Неверный JSON и необъектные записи snapshot отклоняются. Команда CIM, timeout, maxBuffer, скрытое окно, блокировки и запрет продолжения при ошибке не изменены; автоповторов и fallback нет. Это улучшение диагностики, а не установленное исправление причины сбоя на другом ПК.

В обычном пути после assets Minecraft выполняется NeoForge без CIM-проверки на этом переходе. CIM вызывается перед резервированием незавершённой подготовки при явном повторе, при снятии stale lock и в updater до/после загрузки. Само время появления сообщения не доказывает, что ошибка возникла на загрузке assets. Стабильный опубликованный 0.2.6 не содержит эту диагностику и не заменяется этим пакетом.

Новые каталоги для portable и EXE: `dist/portable/KAYVEL-v3S-0.2.7-diagnostic.1` и `dist/setup/KAYVEL-v3S-0.2.7-diagnostic.1`. Прежние артефакты и пользовательский профиль не перезаписываются. Диагностический пакет не опубликован как GitHub Latest; встроенный ZIP позволяет устанавливать лаунчер без загрузки payload по URL. Подпись Ed25519 модпака, TLS и SHA-256 остаются обязательными. Authenticode-подпись EXE по-прежнему не настроена.

Для диагностической версии прошли **435 тестов** без ошибок и пропусков, проверка типов и `git diff --check`. Проверены безопасные коды PowerShell, приватность вывода, неизменность команды/лимитов, отказы при неверном snapshot, работающей Java и другом лаунчере. Настоящий Electron/Chromium в отдельном временном профиле повторно скачал NeoForge 21.1.252 с проверкой **6972019 байт** и SHA-256 `d0345e2a104ce4633065f572310ba6e0dd428bb6a73364cf0c2443ed9f8950ad`, проверил подпись текущего GitHub-манифеста и отмену тела ответа. Это проверка сети текущего компьютера, а не проблемного ПК. В новом portable байты диагностических модулей совпали с проверенной сборкой, ключ/конфиг релиза и план NeoForge совпали с прежним portable; прежние EXE и ZIP 0.2.6 повторно сверены с зафиксированными размерами и SHA-256 без изменений.

## Переносимая папка Windows

```powershell
npm run package:portable -- --output-name KAYVEL-local-preview
```

Результат — `dist\portable\KAYVEL-local-preview\KAYVEL.exe` и файлы рядом. Переносить нужно **всю папку**, не один EXE. Упаковщик использует уже установленный Electron и локальный npm-кэш для production-зависимостей (`npm ci --offline --omit=dev --ignore-scripts`). Сам он не запрашивает сеть и не запускает install-скрипты. Недостающий кэш приводит к остановке без сетевого fallback.

Существующий результат не перезаписывается. При ошибке частичная папка остаётся для проверки; исправьте причину и выберите новое имя, а не повторяйте операцию наугад. Упаковщик переносит только зависимости `main.js` и `preload.cjs` и отклоняет ссылки на прежние модули аккаунтов.

EXE не подписан Authenticode и не является установщиком. Не отключайте защиту Windows ради его запуска. Проверка на текущем компьютере не заменяет проверку на чистой Windows. В папку приложения не входят Minecraft и моды. Начиная с 0.2.5 в неё входит проверенный официальный ZIP Java вместе с лицензиями; runtime извлекается в новый экземпляр только при отсутствии подходящей Java 21. Перед сборкой поместите официальный архив в `bundled/java.zip` по инструкции [bundled/README.md](bundled/README.md); упаковка проверяет размер и SHA-256 без сетевого fallback. Локальные данные по умолчанию хранятся отдельно от EXE в каталоге Electron, а не внутри переносимой папки.

## Профиль и сохранность данных

- В локальной подготовке 0.2.10 в `local-player` внутри `userData` Electron сохраняются только ник и его история. Старые профили версии 2 читаются только ради ника; поля скина игнорируются. Новая запись версии 3 добавляется отдельной ревизией, исходные профили, ревизии и PNG не переписываются и не удаляются. В опубликованных версиях до 0.2.9 включительно PNG сохранялся в `skin-copies\<UUID>\<ник>.png`; это историческое поведение, отсутствующее в 0.2.10. При смене offline-ника может измениться игровая личность и доступ к вещам в мире.

История ограничена 256 ревизиями. Повреждённая или неполная запись блокирует дальнейшие изменения; размер базового файла ограничен 1 500 000 байт, ревизии — 1 501 024 байт, с проверками до и после чтения. После аварии могут остаться частичные файлы или `profile.lock`. Не удаляйте их наугад.

SHA-256 связывает ревизии, но не превращает их в защищённый журнал или резервную копию: удаление последней ревизии или полная локальная подмена могут остаться незамеченными. Блокировки кооперативные; внешние программы способны менять файлы. Резервирование и восстановление требуют отдельного решения.

Если удалить и метку, и манифест, прежний модпак не всегда отличим от отдельной неуправляемой установки NeoForge; новый путь дополнительно требует запись подготовки.

## Отдельный подписанный выпуск

`scripts/prepare-github-release.mjs` локально готовит новый набор из отдельно выбранных `mods\*.jar`, `resourcepacks\*.zip`, `kubejs\client_scripts\*.js`, `kubejs\startup_scripts\*.js`, `kubejs\config\*.json` и PNG в `kubejs\assets\kubejs\textures\block` и `item`. Остальные пути не разрешены. Установщик проверяет каждый родительский каталог вложенных файлов, не принимает ссылки и не перезаписывает существующие файлы. Инструмент требует нового тега, новой папки результата, подтверждения прав и приватного Ed25519-ключа **вне проекта и исходной папки**. Сам инструмент ничего не публикует. Подтверждение оператора не является независимой проверкой лицензий; для известных ограниченных файлов есть дополнительное подтверждение.

Приватные ключи подписи, токены GitHub и серверные пароли нельзя помещать в git, приложение или GitHub Release. Публикуемые конфигурации следует считать общедоступными; поле `auth` в явно согласованном конфиге не должно использоваться как приватный секрет в других средах. После подписи нельзя менять байты манифеста и файлов. Прежний публичный ключ сохранён; URL настроен на v3S. При подготовке и проверке публикации сверяются Ed25519, SHA-256, размеры и точные байты всех выбранных игровых файлов (в текущей подготовке — 91). Исходный ZIP, старые опубликованные файлы и ключи не меняются автоматически.

Подпись подтверждает целостность относительно закреплённого ключа, но не защищает от всех локальных изменений. В лаунчере 0.2.2 численный откат и изменение установленного номера запрещены; прежний EXE 0.2.1 не применяет новые версии к установленному экземпляру.

### Публикация следующего модпака

1. Подготовить новый уникальный численный тег `vX.Y.Z-v3S`, больший текущего, и новую папку результата. Сохранять совместимые версии Minecraft/NeoForge и формат манифеста. Прежние теги, assets, исходный ZIP и существующие build-папки не изменять.
2. Подготовить файлы штатным `scripts/prepare-github-release.mjs`, подписать `manifest.json` прежним Ed25519-ключом вне репозитория. Все URL в манифесте должны вести в `luckystar181/KAYVEL-mods/releases/download/<новый тег>/…`. Изменение ключа или формата потребует отдельного выпуска лаунчера.
3. В новом draft-релизе **репозитория модпака**, не лаунчера, разместить весь набор файлов, `manifest.json` и `manifest.json.sig`. До перевода в latest проверить размеры, SHA-256, подпись и наличие каждого asset. Не публиковать частичный комплект как latest.
4. Опубликовать полный стабильный выпуск и назначить его latest в GitHub. Pre-release/draft не считать каналом обновлений. Проверить фактически скачанные по latest и immutable URL байты: они должны совпадать с локальным подписанным манифестом; сверить подпись и все payload. GitHub latest — изменяемый указатель, а не криптографическая гарантия самого нового номера.
5. Проверить обнаружение, чистую установку и явное обновление старого экземпляра на отдельном тестовом профиле, включая сохранность личных файлов. Установленный модпак с локально изменёнными управляемыми конфигами намеренно даст конфликт; не обходить проверку удалением его метаданных.

Для обновления только модпака не нужно пересобирать установщик или менять его ZIP. Функция updater распространяется отдельным выпуском лаунчера 0.2.2; assets опубликованной 0.2.1 не заменяются.

До публичного размещения игровых служб отдельно согласуются архитектура, защита каналов, секреты, хранилище, резервирование, восстановление и расходы. В этом репозитории нет развёртывания игрового сервера и платной инфраструктуры.
